# 我用一台小米 17 给 Switch 2 当了摄像头

Switch 2 支持 USB 摄像头（GameChat 视频通话、以及一些支持摄像头的游戏）。
但我手上没有能用的摄像头 —— 于是把一台安卓手机改造成了摄像头，顺手写了个 App。

项目地址：[PureCam](../README.md)

---

## 起因：手上的摄像头全都不合用

问题出在**兼容性**上。

Switch 2 对 USB 摄像头的要求是走 **UVC（USB Video Class，免驱摄像头标准）**。
我翻出一个以前买的桌面摄像头接上去，**Switch 2 根本没反应** —— 那颗摄像头走的是厂商私有协议，
需要装驱动才能用，而 Switch 2 显然不可能给它装驱动。

而手头正好有两样东西：

- 一个 **Type-C 转 HDMI 的扩展坞**
- 一块 **HDMI 采集卡**

采集卡的本质就是「把 HDMI 信号包装成一个 UVC 摄像头」。那么链路就很自然了：

```
小米 17 ──Type-C 扩展坞(HDMI 输出)──> HDMI 线 ──> 采集卡 ──USB──> Switch 2
```

手机的相机素质比绝大多数桌面摄像头好得多，还能切超广角 / 长焦。
**唯一的缺口是：需要一个把相机画面"干干净净全屏显示"的 App**，好让 HDMI 输出一份可用的画面。

系统相机应用做不到 —— 它上面永远叠着一层取景框按钮和水印，HDMI 送出去的是整个屏幕。
所以我写了 PureCam。

---

## 踩过的坑

### 1. 采集卡必须是 1080p，2K 的 Switch 2 不识别

这是第一个坑，而且跟 App 完全无关。

**如果采集卡上报的是 2K/1440p 及以上的模式，Switch 2 直接不识别的**。
所以选采集卡时，一定要确认它能输出 **1080p（或 720p/480p）**——很多采集卡支持在多档之间切换，
把它的开关拨到 1080p 就好了。

手机端的输出分辨率也要跟着对齐。PureCam 会自动挑相机硬件**支持**的、
不超过 1920×1080 的档位；如果是 4:3 全画幅模式，上限是 1920×1440。

### 2. 采集卡会把画面拉长 —— 所以我加了个补偿功能

**现象**：画面送进 Switch 2 之后，**整体被拉高了**，上下还带着黑边。

前面提过那条链路：手机屏幕是 19.5:9（小米 17），扩展坞送出去的也是这个比例。
但采集卡内部可能按 4:3 或 16:9 做帧封装，中间任何一环做了**非等比缩放**，画面就会被拉伸。

**这本该是采集卡的锅，但 App 可以提前把画面压回去**，正好抵消掉：

```
补偿值 k = 在 Switch 2 上量到的画面宽度 / 高度
```

- 画面被**拉高**（源 16:9 被塞进 4:3 帧）→ 宽高比约 0.75 → 补偿值调到 **0.75**
- 画面被**压扁**（源 4:3 被塞进 16:9 显示）→ 约 1.33 → 补偿值调到 **1.33**

PureCam 里的做法是在变换矩阵**最后一步**加一个**纯垂直方向的缩放**（`postScale(1, k)`），
绕屏幕中心做，所以水平方向完全不受影响。可调范围 0.50~1.50，步进 0.01，并且**自动记忆**。

配套还有两个东西：

- **`预设`按钮**：一键在 `1.00 → 0.75 → 0.80 → 1.33` 之间循环，多数情况试一遍就对了；
- **`校准图`**：往画面上叠一层**标准正方形网格 + 同心圆**，直接在 Switch 2 上看圆是不是正圆，
  不用猜、也不用拿尺子量。

### 3. 画面自己转了 90°

这个坑最隐蔽，也最花时间。

现象是：切完摄像头，**画面被顺时针旋转了 90°**，而且因为源是 4:3 全画幅，
转完 90° 之后又被拉伸变形。

根因是：Camera2 在创建输出流的时候，相机会把"传感器方向"写进 Surface 的 buffer transform，
`TextureView` 在贴纹理时会**自动帮你转一次** —— 应用层既拿不到这个角度，也改不掉它。
而我下发的旋转角没有把这 90° 扣掉，于是画面被**多转了一次**。

正确写法：

```
实际下发角度 = 净旋转 − Surface 自带旋转(90°) + 用户微调
```

顺带修掉了一个更隐蔽的 bug：判断画面"宽高是否互换"时，
我一开始用的是**下发角度**，结果缩放倍数算成了 **3.33**（把 1280×720 当成 720×1280 来算）——
画面角度是对的，但只剩中间一小块被放大到糊。**用户看到的"变形"其实是这个**。

修完之后实测：

| 模式 | 显示结果 |
| --- | --- |
| 填充（16:9） | 铺满 2400×1080，缩放 1.875 |
| 完整（4:3） | 1440×1080 居中，左右各 480 黑边，缩放 0.776 |

（4:3「完整」模式是默认推荐的 —— 传感器原生就是 4:3，16:9 预览会裁掉上下视野。）

### 4. 相机层从 CameraX 重写成了 Camera2

两个原因：

- **CameraX 选不中物理子摄**。它的 `Camera2CameraFactory` 只返回逻辑摄像头 id，
  而超广角 / 长焦往往藏在逻辑摄像头内部作为**物理子摄**。用 `CameraSelector` 按物理 id 过滤
  会匹配为空然后**静默降级**回主摄 —— 表现就是"后置切了好几个焦段，画面完全不变"。
- **CameraX 掌控不了变换矩阵**。`SurfaceView` 模式下它**直接忽略**应用层的矩阵变换，
  上面那些旋转、填充、拉伸补偿全都做不了。

改 Camera2 之后，用 `OutputConfiguration.setPhysicalCameraId()` 真正把输出流路由到指定镜头，
预览画在自己的 `TextureView` 上，变换矩阵完全自控。

## 一些实用功能

除了上面那些"必须解决"的问题，还加了几个实际用起来很舒服的东西：

| 功能 | 说明 |
| --- | --- |
| 三层 UI 状态机 | 纯净画面 → 点一下出悬浮图标（3 秒自动消失）→ 再点出完整面板。不操作时屏幕上**什么 UI 都没有** |
| 自动息屏保护 | 60 秒无操作关掉屏幕背光。这不是真息屏 —— **只关背光、不改画面**，所以手机屏黑了但投屏画面完全不变，防烧屏也省电 |
| 镜头切换 | 枚举逻辑摄像头 + 全部物理子摄，按 35mm 等效焦距自动命名，循环切换 |
| 对焦锁定 | AF-L：固定机位时画面不会反复拉风箱 |
| 低延迟管线 | 后处理压到 `FAST` 档（主要是去掉**时域降噪**的多帧延迟），约省 33~66ms |
| 画面旋转 | 0/90/180/270 一键循环，兜底个别设备的 Surface 旋转量不是 90° 的情况 |

## 适配范围（说实话）

这个 App 是**给自己用**的，所以适配面很窄，这点必须先讲清楚：

- **只在小米 17 上验证过**。其他机型大概率能用（Camera2 是标准 API），
  但没人替你测过，遇到问题请提 issue。
- **采集卡必须支持 1080p 输出**，2K 的 Switch 2 不识别。
- **接前置摄像头时画面不会镜像**（这是有意为之，视频通话看着更自然；
  需要镜像的话得在采集卡或播放端处理）。

### 一个做不到的事：后台输出

有人可能会想「能不能让 App 挂在后台，手机前台继续干别的」。

**做不到，而且不是实现问题，是架构决定的。**

```
手机屏幕 ──(SurfaceFlinger 合成的 framebuffer)──> Type-C DP 输出 ──> HDMI ──> 采集卡
                    ▲
        送出去的永远是"屏幕此刻显示的内容"
```

HDMI 走 DP Alt Mode 是**屏幕镜像**，送出去的就是屏幕内容。
App 一退到后台，屏幕被别的 app 占据，送出去的也就变成了别的 app —— 逻辑上就不成立。

（唯一可行的分支：如果设备支持**扩展模式**，把外接屏识别为独立显示器而不是镜像，
就能用 `Presentation` 把预览只画到副屏。但手机厂商普遍限制为镜像。）

好在「自动息屏保护」已经解决了"手机屏一直亮着"这个实际痛点。

## 延迟

当前链路的延迟构成大致是：

```
手机端 121ms（曝光 33 + ISP 49 + 绘制 17 + 合成 17 + HDMI 5）
采集卡  65ms
Switch 2 25ms
────────────────────────
合计约 211ms
```

**大头是采集卡那 30~100ms，而且完全不由 App 决定。**
App 端能压的已经压到 `FAST` 后处理这一档了，剩下的优化空间只有 30~60ms，
继续抠不如换一块低延迟采集卡有效。

这个量级拿来做视频通话完全够用。

## 最后

项目已经开源：[PureCam](../README.md)。

技术上最有意思的部分其实是**验证方法** —— 调相机预览时你没法一边改代码一边盯屏幕，
所以整个项目采用了纯像素统计的验证方式（硬边检测、亮度剖面、差异矩阵、相关系数），
不靠肉眼判断"画面到底对不对"。这些脚本和踩坑记录都在
[`docs/development-notes.md`](development-notes.md) 和 [`tools/`](../tools/) 里，
如果你也在调 Android 相机，应该能省下一些时间。
