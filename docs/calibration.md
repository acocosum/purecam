# 画面被拉伸 / 有黑边：校准指南

链路里有三处可能改变画面比例：

```
手机屏幕(19.5:9 或 16:9) --DP 输出--> 采集卡(UVC 帧, 可能是 4:3) --> Switch 2 显示窗口
```

任何一环做了「非等比（anamorphic）缩放」，圆就会变成椭圆。

---

## 1. 最快的诊断：把采集卡插电脑

用 OBS 或系统相机应用打开采集卡，看两件事：

1. **采集卡实际输出分辨率**：`720×480`、`640×480`、`1024×768` 是 4:3；`1280×720`、`1920×1080` 是 16:9。
2. **画面有没有被拉伸**：拿一个正方形物体（或让手机显示本应用的校准图）对着看。

如果采集卡输出 4:3、而你的源是 16:9，采集卡只有两种做法：

- **FIT（等比 + 上下黑边）**：不变形，只有黑边；
- **Stretch（非等比填满）**：横向被压缩 `(4/3)/(16/9) = 0.75`，画面看起来「被拉高」。

---

## 2. 应用内实测校准（不需要电脑）

1. 面板 → `AF/AE` → `校准图`：屏幕叠加**标准正方形网格 + 同心圆**（不参与补偿，是判断基准）。
2. 看 Switch 2 上的图案：
   - 圆变成**竖椭圆**（高 > 宽，即「拉高」）→ 补偿值调到 **< 1.00**
   - 圆变成**横椭圆**（宽 > 高，即「压扁」）→ 补偿值调到 **> 1.00**
3. 用 `拉伸 −` / `拉伸 +` 调到圆变正圆为止（步进 0.01）。数值会自动记忆，下次打开保持。

---

## 3. 想直接算：公式与常见值

设链路对画面做了横向压缩 `a`、纵向压缩 `b`，Switch 2 再各向同性显示。
一个正方格在 Switch 2 上量得宽 `W`、高 `H`，则：

```
补偿值 k = W / H
```

| 现象 | W/H | 补偿值 | 典型链路 |
| --- | --- | --- | --- |
| 画面被拉高（源 16:9 → 4:3 帧 stretch） | 0.75 | **0.75** | 最常见，直接按 `预设` 切到 0.75 试试 |
| 画面被压扁（源 4:3 → 16:9 显示） | 1.33 | **1.33** | 4:3 采集卡 + 16:9 显示窗口拉伸 |
| 轻微变形 | 0.80~0.95 | 微调 | 部分采集卡带 overscan 裁切 |

`预设` 按钮在 `1.00 → 0.75 → 0.80 → 1.33` 之间循环，多数情况先把 0.75 试一遍就能看出来。

### 实现原理

补偿是在变换矩阵的**最后一步**加一个**纯垂直方向的缩放**（`postScale(1, k)`），
绕屏幕中心做，所以水平方向完全不受影响。可调范围 0.50~1.50。

---

## 4. 关于黑边

- 上下黑边通常是 FIT 缩放的产物，属正常，且是不可避免的「安全区」。
- 如果**黑边 + 变形同时出现**，说明链路里某一环先 stretch、再 FIT。
  先按上面的方法把补偿调准，再配合 `16:9框` 输出模式，让有效画面正好落在目标区域里。
- 补偿值 < 1.00 时画面上下会多出黑边，这本来就是「抵消拉伸」的代价；
  如果最终出现在 Switch 2 上的黑边变多了，说明方向调反了。
