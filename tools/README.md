# 验证工具箱

这些是用开发 PureCam 时写的**非可视化验证脚本**：不靠肉眼看截图，只用像素统计（硬边、亮度、相关系数、差异矩阵）来判断"画面到底对不对"。

它们解决的问题很具体：**调相机预览时，你没法一边改代码一边盯着屏幕看**。尤其是
"画面转了 90° 还是没转"、"切了镜头画面真的变了吗"这类问题，肉眼在模拟器的小窗口里看不准，
但像素统计一测就清楚。整个项目的旋转、比例、镜头切换都是靠这些脚本定的案。

## 依赖

```bash
pip install pillow numpy
```

## 脚本一览

### `edge.py` — 找画面硬边（最常用）

```bash
python edge.py 截图.png [亮度阈值]
```

逐列 / 逐行取**最大亮度**，找出预览内容的包围盒。用 max 而不是均值，是为了避免
"场景本身很暗"被误判成"黑边"。

输出内容区间的起止坐标、宽度、中心和边界附近的亮度采样。典型输出：

```
fit.png (2400x1080) 阈值>=1
  内容 x=480..1919 (宽1440)  y=0..1079 (高1080)  中心=(1199,539)
   水平-左/上: 420:  0 440:  0 460:  0 480:253 500:255
```

`460:0 → 480:253` 这种从 0 直接跳到 253 的，就是一条干净的硬边；如果数字是缓慢爬升的，
说明那条边是画面内容而不是预览边界。

**这是量"黑边 / 居中 / 宽高"最可靠的手段。**

### `banddir.py` — 判断条纹方向

```bash
python banddir.py 图1.png [图2.png ...]
```

降采样后比较"相邻列之差"与"相邻行之差"：

- `行间/列间 > 1` → 竖条纹 → 与基线同向（正立）
- `行间/列间 < 1` → 横条纹 → 相对基线转了 90°

用来做**朝向的粗判**：模拟器虚拟场景是竖条色带，一转 90° 就变横条，非常灵敏。

⚠️ **局限**：模拟器虚拟场景会随时间缓慢漂移，同一张基线重复测数值会波动
（实测 `dx/dy` 曾从 1.32 飘到"无明显方向性"）。所以它只能做粗判，
最终结论要落回 `edge.py` 的几何数字，或者干脆人眼看构图。

### `multi.py` — 多图差异矩阵

```bash
python multi.py 图1.png 图2.png 图3.png ...
```

两两求平均绝对像素差，输出矩阵。用来回答"**切了镜头画面真的变了吗**"：

- 同一颗硬件的两张图，只有场景漂移，差异约 **1.2**
- 不同硬件之间差异明显更大（实测 **4.6+**）

有了这个基线，就不用再靠"看起来好像变了"来猜。

### `frontrot.py` — 定 0° vs 180° 的决定性判定

```bash
python frontrot.py 横屏截图.png 竖屏截图.png
```

解决一个很刁钻的问题：**从横屏截图无法区分"旋转 0°"和"旋转 180°"之后又翻转回来**。

思路很巧：摄像头是刚性固定在设备上的，所以**原始 buffer 在横屏和竖屏下完全相同**。
竖屏时两种候选公式给出的角度是相同的（没有歧义），于是竖屏画面就成了一个客观基准 ——
把竖屏图按几何关系转回横屏，再和横屏图求相关系数：

- `rot=0`（即 `sensor+display` 那套）→ **r = +0.97**
- `rot=180`（JPEG 标准式）→ **r = −0.42**

正负号一目了然。

> 注：PureCam v4 起固定横屏，这个脚本在当前版本用不上了；但"用一个无歧义的姿态做基准"
> 这个方法论是通用的，留着作参考。

### `icon_preview.py` — 图标安全区预览

```bash
python icon_preview.py      # 生成 icon_preview.png
```

把自适应图标的矢量几何用 PIL 复刻一遍，**裁到中心 72×72 的安全区**后渲染成图，
用来确认图标在启动器里的真实观感。

两个踩过的坑都固化在脚本里了：

1. **必须裁到 72×72**。108×108 画布中系统只显示中心约 72（其余是出血区），
   不裁的话会误判"内容太小"然后把图形盲目放大，反而超出安全区。
2. **镜片上不能加圆形高光**。脚本里内置了三档变体对比（大镜片无高光 / 小高光 / 原方案），
   一眼就能看出：加了高光之后整个图形会被读成一只"**眼睛**"而不是相机镜头。

## 一条踩坑经验

跑模拟器验证时有几个坑值得记下来：

- Git Bash 会把 `/sdcard/xxx` 当成 Windows 路径改写，adb 命令前要加 `MSYS_NO_PATHCONV=1`；
- `uiautomator dump` 很慢（1~2 秒），如果 UI 有"3 秒自动隐藏"，**点击和 dump 必须写进同一条命令**，
  跨命令调用会因为间隔过长导致面板已经隐藏、点击落空；
- 重装 APK 会撤销已授予的权限，冒烟前先 `adb shell pm grant <pkg> android.permission.CAMERA`，
  否则截到的只是权限对话框。
